# Telebot AI Landing Site — Multi-Language (i18n) Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Ship the landing site in en + zh + es + ja + de (machinery ready for fr/pt), mirroring the app's keyed-catalog architecture — one strings.json source of truth, lint-gated so a raw key can never ship.

**Architecture:** A zero-dependency Node build script renders per-locale static pages from HTML templates + a single `i18n/strings.json` catalog (same shape as the app's `app/Localizable/strings.json`). English stays at the root URL (zero redirect risk); each other language renders at `/zh/`, `/es/`, `/ja/`, `/de/`. Missing keys FAIL the build (the app's ⛔MISSING marker never ships).

**Tech Stack:** Node 18+ stdlib only (fs/path/regex), GitHub Actions (existing pages.yml), Cloudflare Pages mirror, existing vanilla HTML/CSS/JS.

## Approach

### 1. Catalog & language metadata

- **Create `i18n/strings.json`** — same shape as the app: top-level `"languages"` array + `"strings"` map. Values are HTML fragments (inline `<a>`, `<code>`, `<strong>` allowed — needed for docs/guide prose and CJK word order). ~250 keys total:
  - shared chrome (nav links, lang switcher label, footer): ~25
  - index: ~55 (hero, mockup chat lines, strip, 8 bento cells, 3 steps, privacy, requirements, 9 FAQ Q&A, download, feedback)
  - guides index: ~8 · guide article: ~40 · docs: ~60 · changelog: ~45 (reuse app `notes_zh` for the 1.0.2 zh entry) · 404: ~5 · app.js strings: ~12
- **Create `i18n/langs.json`** — per-language metadata: `{ code, nativeName, htmlLang, ogLocale }` for `en, zh, es, ja, de, fr, pt` (nativeName matches the app's `displayName`: English, 中文, Español, 日本語, Deutsch, Français, Português).
- **Untranslated by design** (never tokenized): brand "Telebot AI", code paths (`~/.mlx-serve`), commands (`/remind`), provider names, DMG URLs, `latest.json` (machine contract — build copies verbatim).

### 2. Templates (one per page, tokens replace text)

- Move pages to `templates/`: `templates/index.html`, `templates/guides/index.html`, `templates/guides/run-local-ai-models-on-mac/index.html`, `templates/docs/index.html`, `templates/changelog/index.html`, `templates/404.html`.
- Replace user-facing text with `{{key}}` tokens (whole fragments per string, including surrounding markup). Structure, classes, ids, SVG icons stay inline — no CSS/JS changes needed for layout.
- Head is tokenized per locale: `<html lang>`, `<title>`, description, canonical (`https://telebot.abeaverscart.ca/zh/` …), hreflang alternate block (all languages + `x-default` → root), `og:locale`, localized OG/Twitter text, localized JSON-LD (FAQPage Q&As, SoftwareApplication description, BreadcrumbList names, TechArticle headline).
- Relative asset paths: root pages use `assets/…`, locale pages `../assets/…` — handled by the build (templates use a `{{base}}` prefix token).

### 3. Build script — `scripts/build.mjs` (Node, zero deps)

1. Run `scripts/l10n_check.mjs` (exit 1 on violations).
2. For each language: render every template → `dist/<code>/…` (en → `dist/` root), substituting `{{key}}` and `{{base}}`.
3. Inject per-page `window.I18N = {…}` (the ~12 app.js strings for that language).
4. Copy verbatim: `assets/`, `downloads/`, `latest.json`, `robots.txt`, `_headers`, `_redirects`, `<key>.txt`, `sitemap.xml` (generated), 404 → `dist/404.html` + `dist/<code>/404.html`.
5. Generate `sitemap.xml`: every URL × every language with `xhtml:link` hreflang alternates.
6. **Fail hard on any missing key** (`{{key}}` leftover or `⛔MISSING` marker would otherwise ship).
7. Output `dist/`; add to `.gitignore`.

### 4. Client-side strings — `app.js`

- Replace hardcoded strings (feedback statuses, "Sending…", "Send feedback", "copied ✓", placeholder text) with reads from `window.I18N` (fallback to English if absent, so a template mistake degrades, not breaks). Behavior otherwise unchanged.

### 5. Language switcher (no-JS, all pages)

- `<details class="lang-switcher"><summary>🌐</summary><a …>中文</a>…</details>` in `nav-actions` before the theme toggle — native `<details>` dropdown, zero JS, works on every page. Links point at the same page in each language (`/zh/guides/…` ↔ `/guides/…`), native names, `aria-current="true"` + highlight on the active language.
- `style.css`: `.lang-switcher` styles (matches Apple-clean tokens: glass surface, hairline border, mono labels); compact on mobile. `dist/` class-theme-aware (uses existing `theme-dark` mechanism — no theme changes).

### 6. SEO

- Root URLs unchanged → no redirects, no rank loss. hreflang/canonical/og:locale are additive.
- Single sitemap with hreflang annotations (30 URLs at Batch 1). robots.txt untouched.
- After deploy: re-POST IndexNow (`https://api.indexnow.org/indexnow` with the repo's key) — README documents it.

### 7. Deploy changes

- `.github/workflows/pages.yml`: after checkout → `node scripts/l10n_check.mjs && node scripts/build.mjs` → upload `dist/` instead of `.`.
- README: CF Pages mirror flow becomes `node scripts/build.mjs && rm -rf dist/downloads && npx wrangler pages deploy dist --project-name=telebot-ai-landing --branch=main` (downloads/ still excluded by CF's cap; GH Pages keeps them in dist/).
- `downloads/` + `latest.json` stay committed at repo root exactly as today.

## Risks / tradeoffs / open questions

- **Docs page is the heaviest chunk** (~60 keys, 17.6 KB prose). Included in Batch 1 per the "every surface" rule; can be staged to Batch 2 if the user prefers a faster first ship.
- **Batch 1 language set** — recommendation: zh + es + ja + de (zh because the app already ships it and Chinese users exist; es/ja/de = app Tier 1). Alternative: only zh, or all 7 at once.
- **GH Pages artifact** now includes `dist/` with 3 DMGs (~80 MB total) — well under limits, but build time grows slightly.
- **CF mirror** keeps excluding downloads/ (25 MiB cap) — unchanged, documented.
- **`latest.json` is sacred**: build copies it byte-for-byte; never tokenize. (App ATS/update-check contract.)
- **hreflang x-default** → root (en) — standard practice, no redirect needed.
- **fr/pt** deliberately deferred to stay in lockstep with the app's rollout.
- **Terminology drift risk** between site and app catalogs → mitigation: translations cross-referenced against `app/Localizable/strings.json` during review.
